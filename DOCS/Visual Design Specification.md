# Design System — Social Network

## 1. Общая концепция

Проект представляет собой современную социальную сеть с акцентом на простоту, скорость и комфорт повседневного использования.

Интерфейс должен создавать ощущение спокойствия, доверия и аккуратности. Пользователь не должен испытывать визуальную перегрузку. Все элементы интерфейса подчиняются принципу «контент важнее оформления».

Дизайн не должен выглядеть экспериментальным, футуристичным, игровым или декоративным. Он должен напоминать качественный коммерческий продукт, которым ежедневно пользуются миллионы людей.

Главные качества интерфейса:

* минимализм;
* чистота;
* предсказуемость;
* единообразие;
* современность;
* высокая читаемость.

---

# 2. Визуальное настроение

Интерфейс должен вызывать ассоциации со следующими словами:

* спокойствие;
* доверие;
* профессиональность;
* лёгкость;
* пространство;
* аккуратность;
* современность.

Недопустимы:

* агрессивные цвета;
* кислотные оттенки;
* чрезмерные градиенты;
* неоновое свечение;
* стеклянный (Glassmorphism) стиль;
* Cyberpunk;
* игровые эффекты;
* большое количество теней;
* визуальный шум.

---

# 3. Источники вдохновения

При разработке интерфейса ориентироваться на философию следующих продуктов:

* GitHub
* Linear
* Vercel
* Notion
* Stripe Dashboard
* Discord (структура интерфейса, а не цветовая схема)

Важно не копировать внешний вид, а придерживаться их принципов:

* большое количество свободного пространства;
* минимальное количество цветов;
* строгая сетка;
* простая геометрия;
* акцент на контент.

# 5. Цветовая философия

На странице одновременно должно присутствовать не более:

* одного основного акцентного цвета;
* одного цвета ошибки;
* одного цвета успеха.

Интерфейс не должен превращаться в радугу.

Большая часть интерфейса состоит из белого пространства.

---

# 6. Типографика

Основной шрифт:

Inter

Причины выбора:

* современный;
* отличная читаемость;
* используется большинством современных SaaS-продуктов;
* подходит практически под любой интерфейс.

Вес шрифта:

400 — основной текст

500 — меню

600 — заголовки

700 — важные элементы

Не использовать слишком жирные шрифты.

---

# 7. Пространство

Воздух — главный элемент дизайна.

Лучше оставить пустое место, чем добавить лишний декоративный элемент.

Использовать крупные внутренние отступы.

Основные значения:

```
4
8
12
16
24
32
48
64
```

---

# 8. Скругления

По умолчанию:

```
rounded-xl
```

Маленькие элементы:

```
rounded-lg
```

Кнопки допускается делать полностью круглыми только при наличии иконки.

---

# 9. Тени

Использовать минимально.

Предпочтительно:

```
shadow-sm
```

или

```
shadow
```

Большие размытия запрещены.

---

# 10. Границы

Большинство элементов должны иметь границу.

```
border
border-slate-200
```

Граница является основным способом визуального разделения элементов.

---

# 11. Кнопки

Основная кнопка:

* синяя;
* белый текст;
* небольшая тень.

Вторичная кнопка:

* белый фон;
* серая граница;
* тёмный текст.

Опасное действие:

* красная кнопка.

---

# 12. Карточки

Карточка представляет собой белую поверхность.

Обязательно:

* border;
* rounded-xl;
* небольшой внутренний padding.

Не использовать сложные декоративные элементы.

---

# 13. Формы

Поля ввода:

* белый фон;
* border-slate-300;
* rounded-xl.

При фокусе:

Blue 600.

Красивые эффекты появления запрещены.

---

# 14. Иконки

Использовать Heroicons.

Размер:

20–24 px.

Толщина линий должна быть одинаковой по всему проекту.

---

# 15. Анимации

Анимации должны быть практически незаметными.

Использовать только:

```
transition
duration-200
```

Допустимы:

* hover;
* focus;
* открытие меню.

Запрещены:

* прыжки;
* вращения;
* масштабирование всего интерфейса;
* длительные анимации.

---

# 16. Макеты страниц

Каждая страница состоит из:

Header

↓

Контент

↓

Footer

Максимальная ширина контента:

```
max-w-7xl
```

---

# 17. Tailwind

Использовать исключительно Tailwind CSS.

Запрещается:

* писать собственный CSS (только в крайнем случаи если не льзя решить через Tailwind CSS);
* использовать inline style;
* смешивать Bootstrap и Tailwind.

Все стили описываются исключительно utility-классами Tailwind.

---

# 18. Общий принцип

Перед добавлением любого нового элемента необходимо задать вопрос:

"Помогает ли этот элемент пользователю выполнить задачу?"

Если ответ отрицательный — элемент удаляется.

Главная цель интерфейса — не удивлять пользователя, а позволить ему быстро выполнить нужное действие.

Интерфейс должен выглядеть так, будто его разработала команда зрелого коммерческого продукта, а не как демонстрация визуальных эффектов.
