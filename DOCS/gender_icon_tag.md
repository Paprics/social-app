# `gender_icon` — Django template tag для гендерных иконок

`gender_icon` — пользовательский Django template tag, который преобразует значение гендера в готовую inline SVG-иконку. Компонент централизует выбор SVG-файла, цвет, размер и базовые HTML-атрибуты, чтобы шаблоны не дублировали эту логику.

<a id="purpose"></a>
## Назначение

Вместо ручного выбора файла, цвета и размера в каждом шаблоне используется единый вызов:

```django
{% gender_icon profile.gender %}
```

или:

```django
{% gender_icon profile.gender size=24 %}
```

Тег выполняет пять операций:

1. принимает готовое значение `gender`;
2. находит его конфигурацию в `GENDER_ICONS`;
3. загружает и кэширует содержимое соответствующего SVG;
4. добавляет размер, цвет, CSS-классы и атрибут доступности;
5. возвращает готовый inline SVG либо пустую строку, если иконку вывести невозможно.

Шаблон при этом не знает, где расположен SVG, какой цвет относится к значению гендера и как формируется итоговая разметка.

<a id="api"></a>
## Публичный интерфейс

Сигнатура Python-функции:

```python
gender_icon(gender, size=16)
```

Синтаксис в Django-шаблоне:

```django
{% gender_icon gender %}
{% gender_icon gender size=SIZE %}
```

Тег зарегистрирован через `@register.simple_tag`, поэтому его результат вставляется непосредственно в HTML текущего шаблона.

### Контракт

**Вход:** значение гендера и необязательный размер.

**Выход:** безопасно помеченная строка с inline SVG либо `""`.

Тег не возвращает URL изображения, объект шаблона или HTML `<img>`.

<a id="usage"></a>
## Подключение и использование

Перед вызовом необходимо загрузить библиотеку:

```django
{% load gender_icon %}
```

Несколько библиотек можно подключить одной строкой:

```django
{% load i18n render_image gender_icon %}
```

### Размер по умолчанию

```django
{% gender_icon profile.gender %}
```

Результат получает размер `16 × 16 px`.

### Явный размер

```django
{% gender_icon target_user.profile.gender size=24 %}
```

### В цикле

```django
{% load gender_icon %}

{% for profile in profiles %}
    <div class="flex items-center gap-2">
        {% gender_icon profile.gender size=16 %}
        <span>{{ profile.user.username }}</span>
    </div>
{% endfor %}
```

### С переменной размера

```django
{% gender_icon profile.gender size=icon_size %}
```

Передавать следует непосредственно значение гендера:

```django
{% gender_icon profile.gender %}
```

Не следует передавать объект `Profile` или `User`:

```django
{# Неверный контракт: тег получит строковое представление объекта. #}
{% gender_icon profile %}
```

<a id="arguments"></a>
## Аргументы

| Аргумент | Обязательный | Значение по умолчанию | Ожидаемый формат | Назначение |
|---|---:|---:|---|---|
| `gender` | Да | — | Строка или значение, преобразуемое в строку | Ключ в `GENDER_ICONS` |
| `size` | Нет | `16` | Целое число или строка с целым числом | Одновременно задаёт `width` и `height` |

### `gender`

Текущая конфигурация поддерживает:

| Значение | SVG | Цвет |
|---|---|---|
| `male` | `icons/gender/male.svg` | `#3B82F6` |
| `female` | `icons/gender/female.svg` | `#EC4899` |
| `couple` | `icons/gender/couple.svg` | `#A855F7` |
| `non_binary` | `icons/gender/non_binary.svg` | `#14B8A6` |

Перед поиском в конфигурации значение преобразуется через `str(gender)`. Сопоставление точное и чувствительно к регистру: `male` поддерживается, а `Male` — нет.

### `size`

Значение преобразуется через `int(size)`:

- `24` и `"24"` превращаются в `24`;
- `"24.5"`, `None` и другие непреобразуемые значения заменяются на `16`;
- нулевое и отрицательное значение также заменяется на `16`.

Верхняя граница размера не установлена. Тег технически примет любое положительное целое число.

<a id="flow"></a>
## Алгоритм работы

```text
gender + size
      ↓
проверка пустого gender
      ↓
str(gender) и поиск в GENDER_ICONS
      ↓
нормализация size
      ↓
_load_svg(icon_path)
      ↓
подстановка HTML-атрибутов в открывающий <svg>
      ↓
mark_safe(svg)
      ↓
inline SVG или пустая строка
```

Пошагово:

1. Если `gender` является ложным значением, функция сразу возвращает `""`.
2. `gender` преобразуется в строку и используется как ключ `GENDER_ICONS`.
3. Если ключ отсутствует, возвращается `""`.
4. `size` преобразуется в положительное целое число; иначе применяется `16`.
5. `_load_svg()` читает файл, соответствующий выбранной конфигурации.
6. Ошибка чтения файла перехватывается, после чего возвращается `""`.
7. В первое вхождение `<svg ` внедряются вычисленные HTML-атрибуты.
8. Полученная строка помечается через `mark_safe()` и возвращается шаблону.

<a id="configuration"></a>
## Конфигурация `GENDER_ICONS`

Все соответствия хранятся в `src/core/templatetags/gender_icon.py`:

```python
GENDER_ICONS = {
    "male": {
        "icon": "icons/gender/male.svg",
        "color": "#3B82F6",
    },
    # ...
}
```

Каждая запись содержит два обязательных поля:

| Поле | Назначение |
|---|---|
| `icon` | Путь к SVG относительно `src/static/` |
| `color` | Значение CSS-свойства `color`, внедряемое в `<svg>` |

`GENDER_ICONS` является единой точкой настройки визуального соответствия. Изменение пути или цвета не требует правки шаблонов.

<a id="cache"></a>
## Загрузка и кэширование SVG

Загрузкой занимается внутренняя функция:

```python
_load_svg(icon_path: str) -> str
```

Она собирает путь:

```python
settings.BASE_DIR / "static" / icon_path
```

и читает файл как UTF-8.

Функция декорирована `@lru_cache(maxsize=len(GENDER_ICONS))`. Ключом кэша является `icon_path`, поэтому каждый уникальный SVG обычно читается с диска один раз на процесс Django. Последующие вызовы получают исходный текст из памяти.

Это особенно полезно в списках и результатах поиска, где тег может вызываться десятки раз за один рендер.

### Жизненный цикл кэша

Кэш локален для процесса:

- разные Gunicorn/Daphne workers имеют независимые кэши;
- перезапуск процесса очищает кэш;
- изменение SVG-файла на диске не обновляет уже закэшированное содержимое;
- для принудительного сброса в Python можно вызвать `_load_svg.cache_clear()`.

После замены SVG в развёрнутом приложении нормальный способ обновления — перезапуск процессов приложения.

<a id="rendering"></a>
## Формирование результата

После чтения SVG тег заменяет первое вхождение `<svg ` на открывающий фрагмент с дополнительными атрибутами:

```html
<svg
    width="24"
    height="24"
    style="color:#3B82F6;"
    class="inline-block shrink-0"
    aria-hidden="true"
    ...
>
```

Фактическая разметка остаётся однострочной; форматирование выше показано только для читаемости.

Добавляемые атрибуты:

| Атрибут | Значение | Назначение |
|---|---|---|
| `width` | Нормализованный `size` | Ширина SVG |
| `height` | Нормализованный `size` | Высота SVG |
| `style` | `color:<configured color>;` | Передаёт цвет SVG через `currentColor` |
| `class` | `inline-block shrink-0` | Встраивание в layout и запрет flex-сжатия |
| `aria-hidden` | `true` | Помечает иконку как декоративную |

Цвет будет виден только в тех элементах SVG, которые используют `currentColor`, например `fill="currentColor"` или `stroke="currentColor"`.

В конце применяется `mark_safe(svg)`. Без этого Django экранировал бы `<svg>` как обычный текст.

<a id="errors"></a>
## Обработка ошибок

Компонент использует fail-safe поведение: декоративная иконка не должна приводить к ошибке всей страницы.

| Ситуация | Результат |
|---|---|
| `gender` равен `None`, `""`, `False` или другому ложному значению | `""` |
| Значение отсутствует в `GENDER_ICONS` | `""` |
| `size` нельзя преобразовать в `int` | Размер `16` |
| `size <= 0` | Размер `16` |
| SVG не найден или не читается (`OSError`) | `""` |

Пустой результат не содержит placeholder и не выводит диагностическое сообщение пользователю.

Не перехватываются ошибки неправильной структуры `GENDER_ICONS`, например отсутствие ключа `icon` или `color`. Такие ошибки считаются ошибками разработчика и приведут к исключению.

<a id="architecture"></a>
## Архитектурные границы

`gender_icon` относится к presentation layer и реализует только преобразование:

```text
gender → визуальная конфигурация → inline SVG
```

Тег:

- не зависит от моделей `User` и `Profile`;
- не обращается к ORM;
- не проверяет бизнес-допустимость значения гендера;
- не выполняет проверку прав;
- не обращается к Redis или внешним сервисам;
- не определяет, где именно иконка должна отображаться.

Источник данных обязан передать уже подготовленное значение:

```django
{% gender_icon target_user.profile.gender %}
```

Размещение в `core/templatetags` позволяет использовать тег из шаблонов разных приложений — например, `users`, `search`, `messenger` и `notifications` — без копирования логики.

<a id="extension"></a>
## Изменение и расширение

### Изменить цвет

Исправить поле `color` соответствующей записи:

```python
"female": {
    "icon": "icons/gender/female.svg",
    "color": "#DB2777",
},
```

Все существующие вызовы автоматически начнут использовать новый цвет после перезапуска процесса или перезагрузки модуля.

### Изменить путь к иконке

Исправить поле `icon`:

```python
"couple": {
    "icon": "icons/gender/couple_new.svg",
    "color": "#A855F7",
},
```

### Добавить новое значение

Добавить запись в `GENDER_ICONS`:

```python
"new_value": {
    "icon": "icons/gender/new_value.svg",
    "color": "#64748B",
},
```

После этого существующий шаблон:

```django
{% gender_icon profile.gender size=16 %}
```

сможет отобразить новую конфигурацию без дополнительных условий.

Если новое значение используется в модели или форме, его также необходимо добавить в соответствующие `choices`. Сам тег не синхронизирует UI-конфигурацию с моделью автоматически.

### Изменить размер по умолчанию

Изменить значение в сигнатуре:

```python
def gender_icon(gender, size=20):
```

При таком изменении необходимо также заменить обе ветки fallback, которые сейчас явно используют `16`. Иначе значение по умолчанию и размер при ошибке будут расходиться.

### Изменить общие CSS-классы

Классы задаются в строке, внедряемой через `svg.replace(...)`:

```python
class="inline-block shrink-0"
```

Изменение затронет все места использования тега.

<a id="limitations"></a>
## Ограничения реализации

### 1. Загрузка выполняется напрямую с файловой системы

`_load_svg()` строит путь через `settings.BASE_DIR / "static"`. Django staticfiles finders и `{% static %}` здесь не участвуют. Компонент рассчитан на текущую структуру проекта.

### 2. Модификация SVG основана на строковой замене

Код ищет точную подстроку:

```python
"<svg "
```

Если исходник содержит `<svg>` без пробела или необычно отформатированный открывающий тег, замена не произойдёт. SVG всё равно будет возвращён, но вычисленные `width`, `height`, `style`, `class` и `aria-hidden` не добавятся.

### 3. Возможны дублирующиеся атрибуты

Если исходный `<svg>` уже содержит `width`, `height`, `style`, `class` или `aria-hidden`, тег добавит вторые атрибуты. Дублирующиеся HTML-атрибуты нежелательны, поэтому управляемые тегом атрибуты лучше не фиксировать в исходном SVG.

### 4. Кэш не отслеживает изменение файла

После первой загрузки процесс продолжает использовать закэшированную строку. Простая замена файла без перезапуска процесса может не изменить отображение.

### 5. Ошибки скрываются без логирования

Неизвестное значение и ошибка чтения приводят к пустой строке. Это сохраняет страницу рабочей, но усложняет обнаружение неверной конфигурации.

### 6. Размер не ограничен сверху

Очень большое положительное значение попадёт в HTML без дополнительной проверки. Значение должно формироваться кодом проекта, а не напрямую из недоверенного пользовательского ввода.

<a id="security"></a>
## Безопасность и доступность

### Доверенные SVG

`mark_safe()` отключает HTML-экранирование итоговой строки. Следовательно, SVG-файлы фактически становятся частью DOM страницы.

Механизм допустим только для доверенных ресурсов, контролируемых проектом. Нельзя передавать в него пользовательские SVG или файлы из непроверенных внешних источников.

### Доступность

Тег добавляет:

```html
aria-hidden="true"
```

Это корректно, когда иконка является декоративным дополнением, а значение гендера уже доступно в тексте или другом элементе интерфейса.

Если иконка станет единственным носителем информации, текущий контракт потребуется изменить: значимая информация не должна быть доступна только визуально.

<a id="troubleshooting"></a>
## Диагностика

### Ошибка `Invalid block tag: 'gender_icon'`

Проверить наличие загрузки библиотеки:

```django
{% load gender_icon %}
```

Также проверить имя файла `src/core/templatetags/gender_icon.py` и наличие `__init__.py` в каталоге `templatetags`.

### Тег ничего не выводит

Проверять в следующем порядке:

1. значение передаваемой переменной;
2. точное совпадение значения с ключом `GENDER_ICONS`;
3. поле `icon` выбранной конфигурации;
4. наличие и доступность файла;
5. сообщения или исключения при прямом тестировании функции.

Поскольку штатные ошибки возвращают пустую строку, отсутствие HTML является ожидаемым fail-safe результатом, а не отдельным исключением.

### SVG выводится, но размер, цвет или классы не применились

Вероятная причина — в исходнике не найдено точное вхождение `<svg `. Текущая реализация не разбирает XML/HTML, а выполняет строковую замену.

### SVG имеет размер, но не окрашивается

Проверить, используют ли нужные элементы `fill="currentColor"` или `stroke="currentColor"`. Само свойство `style="color:..."` не переопределяет жёстко заданные `fill` и `stroke`.

### После замены файла показывается старая иконка

Причина — `lru_cache`. Перезапустить процессы приложения либо в отладочной среде вызвать:

```python
_load_svg.cache_clear()
```

<a id="testing"></a>
## Рекомендации по тестированию

Минимальный набор unit-тестов должен проверять:

1. известное значение возвращает SVG;
2. результат содержит правильные `width`, `height`, `color`, классы и `aria-hidden`;
3. размер по умолчанию равен `16`;
4. строковый размер преобразуется в число;
5. неправильный, нулевой и отрицательный размер заменяются на `16`;
6. пустой и неизвестный `gender` возвращают `""`;
7. `OSError` при чтении файла возвращает `""`;
8. повторная загрузка одного пути использует кэш;
9. SVG без подстроки `<svg ` демонстрирует текущее ограничение строковой замены;
10. результат не экранируется Django.

При изменении глобальной конфигурации или SVG между тестами следует очищать кэш:

```python
_load_svg.cache_clear()
```
